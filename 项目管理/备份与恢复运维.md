# 备份与恢复运维

本地 Vault 本身不等于加密存储，也不等于已经可恢复。恢复能力必须分成三层，分别核验。

## Git 规则

1. 仓库位于 `D:\The Memory\The Memory`，不要在外层工作区再套一层仓库。
2. `/私人资料/` 不得进入 Git 历史。
3. `.obsidian/workspace*.json`、`.claudian/`、`.obsidian/plugins/realclaudian/data.json` 不提交。
4. 不要配置自动推送到公开托管。若以后需要远端，只使用私有仓库，并再次确认 ignore 规则。
5. 提交前检查 `git status`，确认没有私密路径。

## 必须在 Obsidian 客户端完成的 Sync 核验

文件审计到此为止。请在 Obsidian 中逐项确认，确认后把结果写回本页：

1. `设置 → Sync`：是否已登录账号，并绑定了名为 The Memory 的远端 Vault。
2. 加密模式是否为端到端加密，以及是否已保存独立密码。丢失该密码即无法恢复远端数据。参见 [Obsidian Sync Security and privacy](https://help.obsidian.md/Obsidian+Sync/Security+and+privacy)。
3. 在另一设备或卸载重装前，是否能完成一次完整下载。
4. 私密层是否包含在 Sync 范围内。若不同步私密层，则必须另有含 `私人资料/` 的加密备份。

未完成以上四项之前，不得把“Sync 已启用”写成“备份已可恢复”。

## 建议的日常顺序

1. 重要批量改写前，运行 `python scripts/create_vault_snapshot.py "D:\The Memory\The Memory" "D:\The Memory\backups"`。
2. 普通层变更用 Git 提交。
3. 私密层变更依赖 ZIP 或已核验的 Sync。
4. 公开导出继续排除整个 `私人资料/`，并清理普通页中的跨私密链接。
